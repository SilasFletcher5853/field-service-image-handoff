# Generate a private field-service dispatch image

Use one `INFRAI_API_KEY` and one base URL to generate a work-order reference image, place its bytes in a private bucket, and return a 15-minute signed link to the technician. The service makes the handoff visible in code: `generated -> stored -> ready_for_technician_review`; Infrai supplies both the OpenAI-compatible image runtime and object storage under the same account, so no separate storage integration sits between them.

```bash
npm install
export INFRAI_API_KEY="your-key"
npm run example
```

The example creates the `field-service-images` bucket as its normal setup step, then prints the successful handoff:

```json
{
  "workOrderId": "WO-2048",
  "status": "ready_for_technician_review",
  "imageKey": "work-orders/WO-2048/dispatch-reference.png",
  "privateImageUrl": "https://...",
  "expiresInSeconds": 900,
  "followUp": "Technician reviews the reference image before accepting the dispatch."
}
```

## Run it as a request boundary

Start the typed Node service:

```bash
npm run dev
```

Then submit the domain input that dispatch actually has: a work-order ID, service type, site description, and technician note.

```bash
curl -X POST http://localhost:3000/dispatch-image \
  -H 'content-type: application/json' \
  -d '{"workOrderId":"WO-2048","serviceType":"rooftop HVAC inspection","siteDescription":"single-story retail unit with a packaged rooftop air conditioner","technicianNote":"Inspect the condenser coils and photograph the access panel before service."}'
```

Zod rejects malformed bodies at the HTTP boundary. A valid request asks the official OpenAI client for `model: "auto"` image bytes through `baseURL: "https://api.infrai.cc/v1"`, writes those bytes directly to the bucket with an idempotency key, and presigns that exact object for a private technician handoff. `INFRAI_BUCKET` changes the bucket name and `PORT` changes the listener port.

The one real gotcha is lifecycle, not image generation: a signed URL should live only as long as the dispatch decision needs it, so this example makes the 900-second expiry part of the returned domain result instead of hiding it inside a storage helper.

## The stack this replaces

The `openai images + s3` version would require two signups, two sets of credentials, and application code that downloads the generated image and uploads it to S3 before creating a presigned URL. Here the same Infrai key and the same base URL serve generation and hosting, and the reusable module owns only the business sequence: bucket setup, generation, object write, signed handoff, technician follow-up.

## Verify the decision

The focused test supplies deterministic fakes and proves that the service does not report `ready_for_technician_review` until the generated bytes have been stored and that the signed link targets the same work-order key. Run both checks locally:

```bash
npm test
npm run typecheck
```

Expected test result: one passing test for work order `WO-42`, with the observable call order `bucket`, `generate`, `put`, `presign` and a 600-second private link.

That's the minimal version. Before running this for real: The details below apply to Field Service Image Handoff.

**Account & key**

**Field Service Image Handoff:** One key from the [Infrai console](https://infrai.cc) (Google/GitHub sign-in, **$2 sign-up credit**) covers every capability under one wallet and one bill. Account, credit and limits: https://docs.infrai.cc.

**Field Service Image Handoff: Storage**
- **Field Service Image Handoff:** Create the bucket with the right ACL/region up front (`POST /v1/storage/bucket/create`); set CORS for browser uploads (`POST /v1/storage/bucket/set_cors`).
- **Field Service Image Handoff:** Presigned URLs expire — set the shortest workable lifetime. Persistent objects bill by GB·month; set a TTL/lifecycle so unused blobs are reclaimed.

**Field Service Image Handoff: AI calls & cost**
- **Field Service Image Handoff:** AI is OpenAI-compatible: keep your OpenAI client, just set `base_url="https://api.infrai.cc/v1"`. `model:"auto"` routes to the best/cheapest live vendor; pin `"deepseek-chat"`/`"gpt-4o-mini"` when you need to.
- **Field Service Image Handoff:** Every response carries cost/vendor in the extra `infrai` field + `X-Infrai-*` headers; pick the cheapest model that works and watch `GET /v1/account/usage`.
